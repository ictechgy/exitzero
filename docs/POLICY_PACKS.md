# Policy packs

Declare the project clients alongside the existing checks in `exitzero.toml`:

```toml
[clients]
adapters = ["cursor", "claude", "pre-push"]
```

Then preview, apply, and diagnose the generated configuration:

```sh
exitzero policy-pack --format json
exitzero policy-pack --apply --format json
exitzero doctor --format json
```

The preview writes nothing. `--check` also writes nothing and exits 1 if the
generated files or their required modes differ. `--apply` preflights every
output before publishing AGENTS, the declared client hooks and the installation
manifest. It saves a plan receipt under `.exitzero/packs/` with path names and
before/after hashes, not the contents of client configuration files. A plan
receipt is configuration evidence, not a passing verification run.

Generated AGENTS text is replaced only within its paired markers. Unrelated
hooks, shared settings and manual instructions remain intact. Malformed files,
symlinks, external Git hook paths and conflicting custom Git hooks are refused.
Explicitly disabled Cursor failClosed or invalid hook budgets require review;
the compiler does not silently turn them into a healthy setup. Apply checks for
concurrent edits, uses atomic per-file writes, and attempts restoration after a
publication error without overwriting newer edits. It is not a filesystem-wide
transaction; inspect a reported incomplete restoration before retrying.

`doctor` treats every declared adapter as required. An undeclared missing adapter
remains optional, and `doctor --adapter NAME` can require an additional one for a
single diagnosis. Removing an adapter from the declaration does not delete its
existing hook or revoke permissions. Review existing configuration separately.

## Hook authority and enforcement

For [permission zones](PERMISSION_ZONES.md), an operator supplies the trusted
baseline independently when preparing the hooks:

```sh
exitzero policy-pack --apply --trust-base TRUSTED_COMMIT
```

The local installation manifest retains the resolved commit. Generated hook
commands use `--use-installed-authority`, so rotating the pin does not rewrite
tracked hook bytes or create a commit-hash self-reference. A missing or invalid
pin fails the hook. It is not taken from a candidate-controlled policy field. A local
hook and its manifest can still be bypassed or edited, so required CI must
provide its own trusted baseline and run a trusted installed copy of ExitZero.
Reapplying with another baseline is an explicit operator action, not an approval
inferred from a test result.

| Configuration | Meaning |
| --- | --- |
| Cursor `failClosed: true` | Generated by default for new owned hooks; doctor diagnoses an explicit false value. |
| Cursor stop | Requests repair feedback; does not provide merge protection. |
| Other client stop hooks | Trust prompts, supported execution modes and timeout behavior remain client-specific. |
| `enforcement = "warn"` | Verification violations are recorded without blocking; execution errors remain errors. |
| `enforcement = "block"` | Default check behavior; a violation fails the gate. |
| Required CI job | Provides merge protection when enforced by the repository's branch rules. |

The compiler does not claim all clients support failClosed, inspect managed or
user-global settings, change remote branch rules, install software, or start a
client. Those runtime facts stay `unverified` in doctor until separately tested.
See [hook contracts](HOOKS.md) for each adapter.
